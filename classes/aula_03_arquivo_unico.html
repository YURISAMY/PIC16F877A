Fundamentos de Arquitetura

0. O Desafio dos 32 Pinos & A Solução com 74HC595

Nas aulas anteriores, aprendemos a controlar saídas simples (LEDs no PORTD) e um display de cristal líquido (LCD 16x2) que possui seu próprio controlador integrado inteligente (o HD44780). Ao nos depararmos com 4 dígitos de 7 segmentos, surge um problema clássico de escassez de pinos de entrada/saída (I/O).

O Dilema da Conexão Direta: Cada display de 7 segmentos possui 8 LEDs internos (7 traços luminosos + 1 ponto decimal). Se ligássemos 4 displays de maneira individual e dedicada ao microcontrolador, precisaríamos de 8 × 4 = 32 pinos! Como o encapsulamento DIP-40 do PIC16F877A possui apenas 33 pinos de I/O no total, não sobraria quase nenhum pino para botões, sensores ou qualquer outra função no sistema.

Para contornar essa limitação física com maestria, a placa ACEPIC PRO V8.0 adota uma união inteligente de dois princípios de engenharia eletrônica:

1
Serialização com Registrador de Deslocamento (CI 74HC595D)

Em vez de gastar 8 fios paralelos para enviar os segmentos (A, B, C, D, E, F, G, DP), usamos um chip conversor serial-paralelo de 8 bits. O PIC16F877A precisa de apenas 3 pinos no PORTE (RE0, RE1, RE2) para transmitir os bits em "fila indiana" em altíssima velocidade.

2
Multiplexação Temporal (TDM) no Barramento de Dígitos

Os 4 displays físicos compartilham rigorosamente os mesmos 8 fios de segmentos vindos do 74HC595. Para exibir números diferentes em cada visor, ligamos um único dígito por vez através de 4 pinos no PORTD (RD0 a RD3), alternando entre eles mais de 100 vezes por segundo. O olho humano enxerga os 4 dígitos acesos ao mesmo tempo!

Resultado: Com apenas 7 pinos do PIC16F877A (3 de controle serial + 4 de seleção de dígitos), controlamos os 4 displays com independência total!

Hardware & Esquemático

1. O Registrador 74HC595D & Conexões na Bancada

Diferentemente do LCD e dos LEDs, o display de 7 segmentos tem seu controle de segmentos feito por um circuito integrado dedicado: o 74HC595D. Este chip contém internamente um registrador de deslocamento de 8 bits seguido de um registrador de armazenamento (Latch) com saídas em paralelo (QA a QH).

🔍 Figura 1: Pinagem do 74HC595D conectado aos pinos RE0, RE1 e RE2 do PIC16F877A. (clique para ampliar)

No 74HC595D, destacam-se 3 conexões cruciais que o PIC utiliza para conversar com o chip:

SER
RE0 → Pino 14: SER (Serial Data Input)

É a porta de entrada dos dados. Por aqui os 8 bits entram um a um, numa espécie de "fila indiana", conforme a ordem de transmissão.

SCK
RE1 → Pino 11: SCK (Shift Register Clock)

É o metrônomo do deslocamento. Cada pulso de subida (transição de 0 para 1) enviado neste pino faz o 74HC595 ler o bit presente em SER (RE0) e empurrar todos os bits internos uma posição para a frente.

RCK
RE2 → Pino 12: RCK (Register Clock / Latch)

É o "tiro de partida" (pulso de trava). Uma borda de subida aqui transfere instantaneamente os dados armazenados no registrador interno para as 8 saídas físicas (QA a QH) que estão ligadas ao display.

Para tornar o código limpo, legível e expressivo, criamos diretivas #define logo no início do firmware:

Mapeamento dos pinos em C 
#define DATA  RE0   // Entrada de dados seriais (SER - pino 14)
#define CLOCK RE1   // Clock de deslocamento (SCK - pino 11)
#define LATCH RE2   // Trava de atualização das saídas (RCK - pino 12)

Podemos observar a disposição do circuito elétrico completo da placa ACEPIC PRO V8.0 na imagem a seguir:

🔍 Figura 2: Esquemático geral: CI 74HC595D, resistores de 330Ω (R29 a R32) e pinos D1 a D4 conectados a RD0..RD3. (clique para ampliar)
Configuração de Hardware Obrigatória (ADCON1 & TRIS)

O procedimento de envio é similar ao do LCD visto na Aula 02. Primeiro, precisamos desativar as funções analógicas existentes nos pinos da Porta E (RE0, RE1 e RE2 são multiplexados com os canais A/D AN5, AN6 e AN7):

  • ADCON1 = 0b00000110; → Desativa todas as funções analógicas nesses pinos e transforma-os todos em pinos estritamente digitais.
  • TRISE0 = 0; TRISE1 = 0; TRISE2 = 0; → Configura os pinos DATA, CLOCK e LATCH como SAÍDAS.
  • TRISD = 0b00000000; → Configura todos os pinos da Porta D (RD0..RD7) como SAÍDAS para controlar a seleção dos 4 dígitos.
Mapeamento de Bits

2. Do Algarismo aos Segmentos: Anatomia & Tabela 0 a 9

Com os pinos configurados como saídas digitais, podemos finalmente mandar conjuntos de 8 bits para acender os segmentos desejados. Mas para isso, é imprescindível entender qual bit controla qual segmento físico do display.

🔍 Figura 3: Disposição física dos segmentos (A: topo, B: dir. superior, C: dir. inferior, D: base, E: esq. inferior, F: esq. superior, G: meio, DP: ponto).

No hardware da ACEPIC PRO V8.0, as saídas do 74HC595 (QA a QH) estão conectadas aos segmentos seguindo uma ordem precisa. O byte transmitido é estruturado exatamente no seguinte formato:

Figura 4: Estrutura do byte: Bit 7 (Ponto) até Bit 0 (Segmento A).

Como calcular o byte para o número 6?

Para formar visualmente o algarismo 6, precisamos acender os segmentos A, C, D, E, F e G. O segmento B permanece apagado (0), assim como o Ponto Decimal (0):

[ Ponto=0 | G=1 | F=1 | E=1 | D=1 | C=1 | B=0 | A=1 ] → 0b01111101 (ou 0x7D em hexadecimal)

Portanto, ao enviar o byte 0b01111101 para o display, ele desenhará com perfeição o número 6!

Tabela Completa de Conversão (0 a 9)

Em vez de calcular os bits manualmente a cada exibição, criamos uma tabela de consulta (lookup table) em C. Para mostrar qualquer número, basta acessar a posição correspondente do vetor: por exemplo, numeros[4] entrega o byte do algarismo 4.

Protocolo de Comunicação

3. O Protocolo Serial & A Função envia7Seg()

Os 8 bits entram no 74HC595 um por vez através do pino DATA (RE0). Para cada bit transmitido, executa-se um ciclo de 3 movimentos:

1. CLOCK = 0; → Prepara a linha de clock no nível baixo.
2. DATA = bit; → Coloca na linha de dados o valor do bit atual (0 ou 1).
3. CLOCK = 1; → A subida do clock faz o chip capturar o valor de DATA e deslocar o registrador!

Se fôssemos enviar o número 6 (0b01111101) de maneira totalmente manual, linha por linha, começando pelo bit mais significativo (Bit 7 - Ponto) até o menos significativo (Bit 0 - A), o código seria:

Envio Manual Bit a Bit (Número 6) 
LATCH = 0;   // 1. Destrava/prepara o latch

CLOCK = 0; DATA = 0; CLOCK = 1;   // Bit 7 (Ponto) = 0
CLOCK = 0; DATA = 1; CLOCK = 1;   // Bit 6 (G)     = 1
CLOCK = 0; DATA = 1; CLOCK = 1;   // Bit 5 (F)     = 1
CLOCK = 0; DATA = 1; CLOCK = 1;   // Bit 4 (E)     = 1
CLOCK = 0; DATA = 1; CLOCK = 1;   // Bit 3 (D)     = 1
CLOCK = 0; DATA = 1; CLOCK = 1;   // Bit 2 (C)     = 1
CLOCK = 0; DATA = 0; CLOCK = 1;   // Bit 1 (B)     = 0
CLOCK = 0; DATA = 1; CLOCK = 1;   // Bit 0 (A)     = 1

LATCH = 1;   // 2. Tiro de partida: joga os 8 bits para as saídas físicas!

Dois Detalhes Cruciais de Engenharia:

  1. Por que o Bit 7 vai primeiro (MSB First)? A cada novo pulso de clock, os bits que já entraram são empurrados para a frente ("deslocamento"). O primeiro bit enviado percorre toda a fila e termina na última saída (QH, conectada ao Ponto). O último bit enviado (Segmento A) permanece na primeira saída (QA). Se enviássemos o bit 0 primeiro, as conexões ficariam todas invertidas!
  2. Por que o LATCH é essencial? Enquanto os bits estão transitando internamente, as saídas do chip ficam congeladas no estado anterior. Somente quando o sinal LATCH sobe de 0 para 1 (o "tiro de partida"), os 8 bits novos são transferidos de forma simultânea e instantânea para os pinos do display. Isso impede ruídos visuais e cintilações espúrias.

Automatizando com Laço: Máscara & Deslocamento

As 8 linhas manuais são idênticas, mudando apenas o valor colocado em DATA. Em C, automatizamos esse processo usando duas operações bit a bit:

  • dado & 0x80 (onde 0x80 = 0b10000000): Uma máscara lógica AND. Ela isola o bit 7. Se o bit 7 de dado for 1, o resultado é verdadeiro (≠ 0); se for 0, o resultado é falso (0).
  • dado = (unsigned char)(dado << 1): Desloca todos os bits do byte uma casa para a esquerda. O bit 6 assume a posição do bit 7, preparando-o para o próximo teste!

Lendo a coluna de DATA de cima para baixo: 0, 1, 1, 1, 1, 1, 0, 1 — exatamente 0b01111101 (número 6)!

A Função Definitiva: envia7Seg() 
void envia7Seg(unsigned char dado) {
    int i;
    LATCH = 0;
    for (i = 0; i < 8; i++) {
        CLOCK = 0;
        if (dado & 0x80) {
            DATA = 1;
        } else {
            DATA = 0;
        }
        dado = (unsigned char)(dado << 1);
        CLOCK = 1;
    }
    LATCH = 1;
}
Primeiro Teste Prático

4. Seleção de Dígitos no PORTD & Primeiro Teste (1 Dígito)

Com a função de envio pronta, resta definir qual dos 4 dígitos físicos vai acender. Como todos os displays compartilham os mesmos 8 segmentos vindos do 74HC595, a seleção de qual visor recebe a energia é feita pelos pinos RD0 a RD3 (indicados como D1 a D4 no esquemático da Figura 2).

Atenção à Lógica Invertida: Na placa ACEPIC PRO V8.0, os transistores de acionamento dos displays operam com lógica invertida:
• Nível Lógico 0 (GND) → LIGA o display correspondente.
• Nível Lógico 1 (VCC) → DESLIGA o display correspondente.

Dígito 1 (Milhar / Esquerda) RD0 0b11111110 0xFE Apenas D1 aceso
Dígito 2 (Centena) RD1 0b11111101 0xFD Apenas D2 aceso
Dígito 3 (Dezena) RD2 0b11111011 0xFB Apenas D3 aceso
Dígito 4 (Unidade / Direita) RD3 0b11110111 0xF7 Apenas D4 aceso

Programa 1: Exibindo o número 6 no Dígito 1

Vamos juntar a configuração das portas, a função envia7Seg() e a ativação exclusiva do RD0:

main.c — Teste Estático de 1 Dígito 
#include <xc.h>

#pragma config FOSC = HS
#pragma config WDTE = OFF
#pragma config PWRTE = ON
#pragma config BOREN = ON
#pragma config LVP = OFF

#define _XTAL_FREQ 8000000

#define DATA  RE0
#define CLOCK RE1
#define LATCH RE2

void envia7Seg(unsigned char dado) {
    int i;
    LATCH = 0;
    for (i = 0; i < 8; i++) {
        CLOCK = 0;
        if (dado & 0x80) {
            DATA = 1;
        } else {
            DATA = 0;
        }
        dado = (unsigned char)(dado << 1);
        CLOCK = 1;
    }
    LATCH = 1;
}

void main(void) {
    ADCON1 = 0b00000110;   // Libera pinos digitais

    TRISE0 = 0;            // DATA, CLOCK e LATCH como saídas
    TRISE1 = 0;
    TRISE2 = 0;
    TRISD  = 0b00000000;   // RD0..RD7 como saídas de seleção

    PORTD = 0b11111110;    // Liga apenas o Dígito 1 (nível 0 ativa)
    envia7Seg(0b01111101); // Envia o padrão de segmentos do número 6

    while (1) {
        // Mantém a exibição estática
    }
}

Persistência da Visão

5. Dois Dígitos: O Desafio & A Multiplexação Temporal

Imagine que você queira exibir o número 47 no display. O Dígito 1 precisa exibir o 4 e o Dígito 2 precisa exibir o 7. Porém, os dois visores estão conectados fisicamente às mesmas saídas do 74HC595!

O que acontece se ligarmos RD0 e RD1 juntos? Ambos os dígitos mostrarão exatamente a mesma coisa ao mesmo tempo! Se você enviar o 4, verá 44; se enviar o 7, verá 77. Não há como enviar valores diferentes simultaneamente por um único conjunto de fios.

A solução é a Multiplexação Temporal (Varredura Rápida): mostramos um dígito de cada vez, trocando de visor em alta velocidade. O olho humano retém a luz por uma fração de segundo (fenômeno da persistência retiniana). Se a taxa de atualização for superior a 50 Hz, o cérebro funde as imagens e percebe os dois dígitos continuamente acesos sem qualquer cintilação!

1
Apagar Todos os Dígitos (PORTD = 0b11111111;)

Elimina o efeito fantasma. Se o visor anterior continuasse ligado enquanto os novos segmentos são atualizados, ele exibiria momentaneamente o número errado!

2
Enviar os Segmentos do Dígito da Vez (envia7Seg(...))

O 74HC595 recebe o byte correto (ex: a dezena) e trava o valor nas saídas com o Latch.

3
Ligar Apenas o Dígito Correspondente (PORTD = 0b11111110;)

Coloca nível 0 no transistor do visor escolhido (RD0 para a dezena, RD1 para a unidade).

4
Aguardar um Breve Intervalo (__delay_ms(2);)

Dá tempo hábil para a luz dos LEDs sensibilizar os receptores da retina humana com brilho nítido.

Separando em Dezena e Unidade

Para separar o número 47 em seus dois algarismos, usamos divisão inteira (/) e resto da divisão (%):
• Dezena: 47 / 10 = 4
• Unidade: 47 % 10 = 7

Contador de 00 a 99 com Multiplexação (2 Dígitos) 
void main(void) {
    ADCON1 = 0b00000110;

    TRISE0 = 0;
    TRISE1 = 0;
    TRISE2 = 0;
    TRISD  = 0b00000000;

    unsigned int contador = 0;
    unsigned int tempo_aux = 0;

    while (1) {
        unsigned char dezena  = contador / 10;
        unsigned char unidade = contador % 10;

        // 1. Dezena no primeiro dígito (RD0)
        PORTD = 0b11111111;            // Apaga tudo (evita fantasma)
        envia7Seg(numeros[dezena]);    // Envia segmentos
        PORTD = 0b11111110;            // Liga só o RD0
        __delay_ms(2);

        // 2. Unidade no segundo dígito (RD1)
        PORTD = 0b11111111;            // Apaga tudo
        envia7Seg(numeros[unidade]);   // Envia segmentos
        PORTD = 0b11111101;            // Liga só o RD1
        __delay_ms(2);

        // 3. Contagem de varreduras para avançar o número sem travar a tela!
        tempo_aux++;
        if (tempo_aux >= 100) {
            contador++;
            tempo_aux = 0;

            if (contador > 99) {
                contador = 0;
            }
        }
    }
}

3 Dúvidas Frequentes de Bancada:

1. Por que apagar tudo antes de trocar o dígito? O LATCH atualiza os segmentos instantaneamente. Se o visor anterior ainda estivesse aterrado (ligado), ele mostraria por um microssegundo os traços do novo dígito, gerando um rastro borrado e fantasma no display.

2. Por que o delay de 2 ms? Uma rodada pelos 2 dígitos leva 2 + 2 = 4 ms, o que equivale a aproximadamente 250 varreduras por segundo (250 Hz). Isso está muito acima do limiar de percepção humana (50 Hz), garantindo estabilidade perfeita e excelente brilho.

3. Por que usar tempo_aux em vez de __delay_ms(500)? Esta é a dúvida mais comum! Se você colocasse um __delay_ms(500) no final do loop, o microcontrolador ficaria paralisado nessa linha por meio segundo. Durante esse tempo, ninguém estaria alternando os dígitos, e apenas o último dígito ficaria aceso sozinho! Por isso a multiplexação nunca pode ser interrompida: o ritmo do tempo é contado pelas próprias voltas da varredura (100 voltas × 4 ms ≈ 400 ms por incremento).

Solução Completa

6. Quatro Dígitos: Milhar, Centena, Dezena e Unidade

Para estender o sistema para os 4 visores da placa ACEPIC PRO V8.0 (de 0000 a 9999), basta generalizar a decomposição matemática e acionar os pinos RD0, RD1, RD2 e RD3 em sequência.

Decomposição Matemática de 4 Algarismos:

Tomemos como exemplo o número 1234:

• Milhar:   1234 / 1000 = 1
• Centena: (1234 / 100) % 10 = 12 % 10 = 2
• Dezena:  (1234 / 10) % 10 = 123 % 10 = 3
• Unidade: 1234 % 10 = 4

Encapsulamos todo o bloco de varredura na função modular mostraNumero(unsigned int valor). Cada ciclo completo consome 4 dígitos × 2 ms = 8 ms (~125 Hz). Portanto, 50 iterações de tempo_aux resultam em 50 × 8 ms ≈ 400 ms por incremento:

main.c — Firmware Definitivo Compilável (4 Dígitos) 
#include <xc.h>

// ==============================================================
// FUSES DE HARDWARE (PIC16F877A)
// ==============================================================
#pragma config FOSC = HS        // Cristal oscilador externo de 8 MHz
#pragma config WDTE = OFF       // Watchdog Timer desligado
#pragma config PWRTE = ON       // Power-up Timer ligado (estabilização)
#pragma config BOREN = ON       // Brown-out Reset ligado
#pragma config LVP = OFF        // Gravação em baixa tensão desativada (libera RB3)

#define _XTAL_FREQ 8000000

// Mapeamento dos pinos do 74HC595
#define DATA  RE0
#define CLOCK RE1
#define LATCH RE2

// Tabela de conversão visual de 0 a 9
unsigned char numeros[10] = {
    0b00111111, // 0
    0b00000110, // 1
    0b01011011, // 2
    0b01001111, // 3
    0b01100110, // 4
    0b01101101, // 5
    0b01111101, // 6
    0b00000111, // 7
    0b01111111, // 8
    0b01101111  // 9
};

// ==============================================================
// ENVIO SERIAL DE 8 BITS PARA O 74HC595
// ==============================================================
void envia7Seg(unsigned char dado) {
    int i;
    LATCH = 0;
    for (i = 0; i < 8; i++) {
        CLOCK = 0;
        if (dado & 0x80) {
            DATA = 1;
        } else {
            DATA = 0;
        }
        dado = (unsigned char)(dado << 1);
        CLOCK = 1;
    }
    LATCH = 1;
}

// ==============================================================
// VARREDURA COMPLETA DOS 4 DÍGITOS (MULTIPLEXAÇÃO)
// ==============================================================
void mostraNumero(unsigned int valor) {
    unsigned char milhar  = (valor / 1000) % 10;
    unsigned char centena = (valor / 100) % 10;
    unsigned char dezena  = (valor / 10) % 10;
    unsigned char unidade = valor % 10;

    // 1. Milhar (RD0)
    PORTD = 0b11111111;            // Apaga todos os visores
    envia7Seg(numeros[milhar]);    // Carrega segmentos
    PORTD = 0b11111110;            // Liga apenas RD0 (nível 0)
    __delay_ms(2);

    // 2. Centena (RD1)
    PORTD = 0b11111111;
    envia7Seg(numeros[centena]);
    PORTD = 0b11111101;            // Liga apenas RD1
    __delay_ms(2);

    // 3. Dezena (RD2)
    PORTD = 0b11111111;
    envia7Seg(numeros[dezena]);
    PORTD = 0b11111011;            // Liga apenas RD2
    __delay_ms(2);

    // 4. Unidade (RD3)
    PORTD = 0b11111111;
    envia7Seg(numeros[unidade]);
    PORTD = 0b11110111;            // Liga apenas RD3
    __delay_ms(2);
}

// ==============================================================
// PROGRAMA PRINCIPAL
// ==============================================================
void main(void) {
    ADCON1 = 0b00000110;           // Desativa analógicos nos pinos PORTE e PORTA

    TRISE0 = 0;                    // DATA como saída
    TRISE1 = 0;                    // CLOCK como saída
    TRISE2 = 0;                    // LATCH como saída
    TRISD  = 0b00000000;           // Barramento PORTD (RD0..RD3) como saídas

    unsigned int contador = 0;
    unsigned int tempo_aux = 0;

    while (1) {
        // Mantém a multiplexação ativa a cada instante
        mostraNumero(contador);

        // Controla a cadência de avanço da contagem
        tempo_aux++;
        if (tempo_aux >= 50) {
            contador++;
            tempo_aux = 0;

            if (contador > 9999) {
                contador = 0;
            }
        }
    }
}

7. Desafios de Projeto & Soluções Comentadas

Coloque seus conhecimentos em teste resolvendo os três desafios práticos que frequentemente surgem em projetos comerciais de instrumentação embarcada.

Desafio 1: Ponto Decimal Contínuo

Faça com que o Ponto Decimal do segundo dígito (centena) permaneça aceso o tempo todo, transformando a leitura em um valor formatado com casa decimal (por exemplo, 25.40 ou 12.34). Dica: O ponto decimal é o bit 7 do byte.

💡 Ver Solução do Desafio 1

Resposta: Dentro da função mostraNumero(), no bloco da centena, enviamos numeros[centena] | 0b10000000 (ou | 0x80). O operador bitwise OR (|) preserva os segmentos originais do número e força exclusivamente o Bit 7 (Ponto) para nível 1: 

// No bloco de envio do segundo dígito (Centena):
envia7Seg(numeros[centena] | 0b10000000);

Desafio 2: Eliminar Repetições com Vetor e Laço for

Na função mostraNumero(), o bloco de varredura aparece 4 vezes idêntico, alterando apenas o algarismo e o valor de seleção de PORTD. Reescreva a função de forma enxuta utilizando um laço for.

💡 Ver Solução do Desafio 2

Resposta: Armazenamos os 4 algarismos calculados em um vetor digito[4] e os 4 valores de acionamento de PORTD em outro vetor selecao[4], percorrendo ambos com o mesmo índice i: 

const unsigned char selecao[4] = {
    0b11111110, // D1 (RD0)
    0b11111101, // D2 (RD1)
    0b11111011, // D3 (RD2)
    0b11110111  // D4 (RD3)
};

void mostraNumero(unsigned int valor) {
    unsigned char digito[4];
    unsigned char i;

    digito[0] = (valor / 1000) % 10;
    digito[1] = (valor / 100) % 10;
    digito[2] = (valor / 10) % 10;
    digito[3] = valor % 10;

    for (i = 0; i < 4; i++) {
        PORTD = 0b11111111;            // Apaga tudo
        envia7Seg(numeros[digito[i]]); // Envia segmentos
        PORTD = selecao[i];            // Liga o dígito da vez
        __delay_ms(2);
    }
}

Desafio 3: Supressão de Zeros à Esquerda (Blanking)

Atualmente, o número 7 é exibido como 0007 e o número 47 como 0047. Em equipamentos industriais, é comum apagar os zeros à esquerda para tornar a leitura limpa (exibindo 7 e 47). Dica: Para apagar um visor, envie 0b00000000 em vez de numeros[...], mas garanta que o zero da unidade seja sempre mostrado quando o número for realmente 0!

💡 Ver Solução do Desafio 3

Resposta: Verificamos se o valor é menor que 1000 para apagar o milhar, menor que 100 para apagar a centena, e menor que 10 para apagar a dezena: 

void mostraNumeroSemZeros(unsigned int valor) {
    unsigned char m = (valor / 1000) % 10;
    unsigned char c = (valor / 100) % 10;
    unsigned char d = (valor / 10) % 10;
    unsigned char u = valor % 10;

    // 1. Milhar: apaga se for zero
    PORTD = 0b11111111;
    envia7Seg((valor < 1000) ? 0b00000000 : numeros[m]);
    PORTD = 0b11111110;
    __delay_ms(2);

    // 2. Centena: apaga se valor for menor que 100
    PORTD = 0b11111111;
    envia7Seg((valor < 100) ? 0b00000000 : numeros[c]);
    PORTD = 0b11111101;
    __delay_ms(2);

    // 3. Dezena: apaga se valor for menor que 10
    PORTD = 0b11111111;
    envia7Seg((valor < 10) ? 0b00000000 : numeros[d]);
    PORTD = 0b11111011;
    __delay_ms(2);

    // 4. Unidade: sempre exibe (mesmo que seja zero)
    PORTD = 0b11111111;
    envia7Seg(numeros[u]);
    PORTD = 0b11110111;
    __delay_ms(2);
}

🏎️ 8. Pista Rápida (Passo a Passo de Bancada)

Para quem já possui experiência com microcontroladores e deseja apenas o roteiro prático e objetivo de montagem e gravação na bancada, siga a ordem direta dos passos a seguir:

1
Pinagem e Ligações Físicas na Placa ACEPIC PRO V8.0

Certifique-se das conexões de controle do CI 74HC595D e da seleção dos transistores de dígitos:

  • Controle Serial (PORTE): RE0 = DATA (Pino 14 - SER), RE1 = CLOCK (Pino 11 - SCK), RE2 = LATCH (Pino 12 - RCK).
  • Seleção de Dígitos (PORTD): RD0 = Dígito 1 (Milhar), RD1 = Dígito 2 (Centena), RD2 = Dígito 3 (Dezena), RD3 = Dígito 4 (Unidade).
  • Lógica de Acionamento: Transistores em nível baixo (0 liga, 1 desliga).

Função de Envio Serial ao 74HC595 (envia7Seg)

Transmite 8 bits MSB-first através da máscara & 0x80 e trava as saídas com o LATCH:

Função envia7Seg() 
void envia7Seg(unsigned char dado) {
    int i;
    LATCH = 0;
    for (i = 0; i < 8; i++) {
        CLOCK = 0;
        if (dado & 0x80) {
            DATA = 1;
        } else {
            DATA = 0;
        }
        dado = (unsigned char)(dado << 1);
        CLOCK = 1;
    }
    LATCH = 1;
}

Função de Varredura e Multiplexação (mostraNumero)

Executa o ciclo apagar → enviar → ligar → delay(2ms) para os 4 visores:

Função mostraNumero() 
void mostraNumero(unsigned int valor) {
    unsigned char m = (valor / 1000) % 10;
    unsigned char c = (valor / 100) % 10;
    unsigned char d = (valor / 10) % 10;
    unsigned char u = valor % 10;

    PORTD = 0b11111111; envia7Seg(numeros[m]); PORTD = 0b11111110; __delay_ms(2);
    PORTD = 0b11111111; envia7Seg(numeros[c]); PORTD = 0b11111101; __delay_ms(2);
    PORTD = 0b11111111; envia7Seg(numeros[d]); PORTD = 0b11111011; __delay_ms(2);
    PORTD = 0b11111111; envia7Seg(numeros[u]); PORTD = 0b11110111; __delay_ms(2);
}
